API overview

Six concepts cover the whole API.

/v1/paymentsPaymentsAuthorize, capture, void, refund. One resource across every provider; route details attached./v1/tokensTokens & customersTokenize card data via hosted fields; store methods against customers for recurring use./v1/merchantsMerchantsFor platforms and tenants: create and configure merchants programmatically./v1/routing-profilesRoutingRead and (with permission) manage routing profiles and cascade rules./v1/disputesDisputesList chargebacks, upload evidence, track deadlines and outcomes.webhooksWebhooksSigned, retried events for every state change. Idempotent on event id.

Sandbox

Simulate providers, declines and cascades.

The sandbox is a separate environment with its own keys. Test card numbers and amounts trigger specific outcomes so you can exercise your error handling, 3DS flows and webhook consumers before go-live.

TriggerOutcome
4242 4242 4242 4242Authorized on primary
4000 0000 0000 0002Hard decline — not cascaded
4000 0000 0000 0101Soft decline → cascade to backup
4000 0000 0000 32203DS challenge required
amount = 99999Provider timeout → health demotion
amount = 40001Dispute created 60s after capture
